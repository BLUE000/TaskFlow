# 要件定義書 (Requirements Definition)

## 1. システム化の背景と目的

### 背景
* 所有するタスクの増加に伴い、各タスクのスケジュール立案や進捗管理が十分にできていない。
* タスク以外の月次固定予定（定例イベント等）も混在しており、整理が必要である。

### 目的
* 自身のタスクと固定予定を一括管理し、全体を容易に俯瞰できるようにする。
* 用途（目的）に応じて、不特定多数への公開・非公開（表示/非表示）を制御できる機能を提供する。

## 2. アクターと権限

| アクター | 概要 | 権限・操作範囲 |
| :--- | :--- | :--- |
| **管理者 (ユーザー本人)** | 予定を管理する当事者（1名） | すべての予定（公開・非公開含む）の登録・編集・削除、全予定の閲覧。要ログイン認証。 |
| **一般閲覧者 (不特定多数)** | 外部の第三者 | 公開設定された予定のみ閲覧可能。認証不要（専用URLからアクセス）。 |

## 3. 取り扱うデータ・予定の種類

システムで管理する予定は以下の3種類とし、すべての予定に「公開フラグ（公開/非公開）」および「フィルタ用の専用フラグ（タグ/カテゴリ）」を付与する。

1. **簡易予定 (イベント)**
   * 手帳に記載するような、日時指定のみのシンプルな予定（例：定例ミーティング、プライベートの予定等）。
2. **期間のある作業スケジュール**
   * 開始日時と終了日時（期間）を持つ予定（例：旅行、出張、特定フェーズの作業等）。
3. **個人タスク**
   * 進捗管理が伴うタスク。以下の属性を持つ。
     * **進捗状況**（未着手・進行中・完了などのステータス）
     * **優先度**（タスクの重要度。設定時は数値用のスピンボックスを使用）
     * **重み/所要時間**（作業にかかる時間（単位: 時間）。設定時はスピンボックスを使用。色のついたアイコンで視覚的に表現する）
     * **作業時間枠の割り当て**（どの時間帯枠に属するかの指定。期間が設定されているタスクの場合は、期間内の各日付・時間枠に対して、個別に作業時間を割り振ることができる（子データとして保持））
4. **やることメモ (日付未定)**
   * カレンダー上の日付や時間枠が決まっていない、To-Doの備忘録メモ（例：ほしいものリスト、将来やるべきタスク候補、タスクのアイディア等）。
   * 開始日時や終了日時は設定されず、一般カレンダー画面には非表示。管理コンソールおよび C++ デスクトップクライアントからのみ操作・管理可能。

## 4. 主な機能要件

### 4.1. 予定管理・編集機能（管理者向け）
* **予定の個別管理**
  * 簡易予定・期間予定・個人タスクを個別登録・編集・削除できる。
  * 入力フォームの「予定の種類」や「カテゴリ」等の主要項目に、操作ミスを防止するための入力補助説明（HELP）を表示すること。
* **繰り返し予定機能（同月内限定）**
  * 期間予定 (period) に対して「毎日」「毎週同じ曜日」「平日のみ（月〜金）」といった繰り返し（コピー）設定を行えること。
  * 超長期設定による予定のゾンビ化（削除し忘れや範囲不明による残存）を防ぐため、**繰り返しコピーの生成範囲は「開始日の属する月（同月内）の月末まで」に制限**されること。
  * 繰り返し生成された予定群を一括管理するため、共通の `recurrence_group_id` を持たせること。
  * 繰り返し予定の編集・削除の際、「この予定のみ変更・削除」または「シリーズ全体を変更・削除」を選択できること。
* **タスク分割（セグメント管理）**
  * `period` または `task` タイプの予定について、1タスクが複数の非連続な期間（セグメント）を持てること。
  * 管理画面からセグメントの追加・削除ができること（「＋ 期間を追加」ボタンによる動的UI）。
  * ガントチャート上では、同一タスクの複数セグメントが同じ行に間隔を空けて並んで表示されること。
  * セグメントが未設定の場合は、従来通り `schedules.start_at / end_at` の単一期間として扱うこと（後方互換）。
  * 日別作業時間配分（`schedule_allocations`）はセグメント単位で紐付け可能とし、既存データはセグメント未設定（`segment_id = NULL`）として互換を維持すること。
* **時間枠（時間帯）の定義機能**
  * 1日の中の作業時間枠（例：「午前枠 10:00〜13:00（3時間）」「午後枠 13:00〜22:00（9時間）」など）を定義・編集できる。
  * フォーム入力項目（「時間枠の名前」や「許容作業時間 (limit_hours)」）の役割に関する入力補助説明（HELP）を表示すること。
* **公開/非公開コントロール**
  * 登録時のデフォルト設定は「非公開」とする。
  * 予定ごとに公開/非公開を個別に切り替えられる。
  * 予定一覧において、複数の予定を選択して一括で公開/非公開を変更できる「一括設定機能」を提供する。
* **管理者パスワード変更機能**
  * 管理者画面から、自身の管理者用ログインパスワードを安全に変更できる機能を提供する。
* **Discord Webhook URL の登録と案内**
  * Discord Webhook登録時に、Discord側のチャンネル設定からウェブフックURLを取得する手順（HELP）を入力欄の下に分かりやすく明記すること。
* **やることメモ管理および移行機能**
  * カレンダーの日付が決まっていない「やること（To-Do）」をメモとして登録・編集・論理削除できる。
  * メモの登録時は、日付入力欄や繰り返し、Discord通知といった項目は不要（非表示）とする。
  * メモ一覧からカレンダー上の予定やタスクに簡単に「移行」できるUIを提供する。移行時は、メモ情報を受け継いだ状態で日付や時間枠を割り当てて保存するだけで、自動的にタイプが変更されて移行が完了する構成とする。


### 4.2. 予定表示機能（ビュー）
* **カレンダー表示**
  * 月単位の表示と週単位の表示をスムーズに切り替えられること。
  * カレンダーおよび週間スケジュールの開始曜日は日曜日とすること。
  * 内閣府が提供する祝日CSVを取り込むことで、カレンダー上に日本の祝日情報を表示できること。
  * 一般閲覧者の混乱を避けるため、技術的なシステム名やサブタイトル表記はヘッダーから排除し、簡素なレイアウトにすること。
  * カレンダー画面下部の余白部分に、コピーライトおよび主要な使用技術・ライブラリ（TaskFlow, TransCipher, Qt 6, PHP, MySQL, SQLite 3）のクレジットを掲載すること。
  * 期間が設定されたタスクについても、ガントチャート同様に開始〜終了の期間にわたって（連日表示）カレンダー上に描画されること。
* **祝日データの取り込み・更新画面**
  * 管理者向けに祝日CSVのインポート機能を提供する。
  * この画面には、内閣府HPからのCSVダウンロード手順やインポート手順をわかりやすく記載（手順書を同梱）すること。
* **ガントチャート表示**
  * 期間を持つ作業スケジュールやタスクについて、進捗や前後関係が直感的にわかるタイムライン形式での表示・管理を行えること。
* **フィルタリング**
  * 専用フラグ（カテゴリ）により、用途や目的（仕事、プライベート、勉強など）に応じた予定の絞り込み表示を行えること（複数選択対応）。
  * URLパラメータ（`?categories=xxx,yyy`）を指定してアクセスすることで、初期表示時に特定のカテゴリで自動絞り込みを行うこと。また、画面上のフィルター選択状態に合わせてブラウザのアドレスバーのURLパラメータもリアルタイムで連動して更新されること。
  * カテゴリ絞り込みの項目（チップ一覧）は、ユーザー操作によって表示・非表示をトグルで切り替えられること。

### 4.3. 負荷管理・警告機能
* **重みの可視化**
  * タスクに設定された「重み（所要時間）」を、色のついたアイコンで直感的に判別可能にする。
* **時間枠ごとの負荷オーバー警告**
  * 1日において、ある時間枠に割り当てられたタスクの作業時間の合計値（期間タスクの場合は、その日に割り振られた日別作業時間の値）が、その時間枠の許容時間（例: 10:00〜13:00であれば3時間）を超過した場合、カレンダーやチャート上で負荷オーバーである旨の警告表示（枠のハイライトや警告メッセージ・アイコン表示等）を行うこと。
  * また、許容時間に対して作業時間が不足しているか、あるいは超過しているかの状況（現在の合計時間）をセル上で確認できること。

### 4.4. 閲覧制限（セキュリティ・共有）
* **管理者画面（編集・全表示）**：要ログイン。非公開予定を含むすべての予定・時間枠設定・祝日更新が確認・操作可能。管理者パスワードの変更機能を提供する。
* **共有画面（閲覧用カレンダー）**：
  * デフォルトではログイン不要で、公開に設定された予定のみがカレンダー/ガントチャートで表示され、フィルタ機能も利用可能。
  * 画面上から「管理者ログイン」を行うことで、一般画面をリロードしたうえで非公開予定も含めて閲覧・負荷警告の集計が行える機能を提供する。ログイン中はログアウト操作が可能。

### 4.5. Discord通知機能
* **Webhook URLの複数登録・管理**
  * 管理者は事前に複数のDiscord Webhook URL（例：「仕事用」「プライベート用」など）を登録・管理できる。
* **予定ごとの通知先選択**
  * 各予定（タスク・イベント）の作成・編集画面にて、どのWebhook URLを使用して通知を送るかを個別または「通知なし」から選択できる。
* **通知の実行**
  * 指定された条件や予定日時に応じて、選択したWebhook URL宛てにDiscord通知を送信する。

## 5. 非機能要件

### 5.1. 動作環境
* **サーバーサイド**：PHP 8.1.34（Webサーバー: Apache）
* **データベース**：MySQL 8.0（PDO MySQL接続）
* **主要な対象デバイス**：PCブラウザ（操作用）およびスマートフォンブラウザ（閲覧用/レスポンシブ対応）

### 5.2. セキュリティ
* 管理画面へのアクセスはログイン認証（セッション管理）によるセキュリティを確保する。
* 不正アクセスやパラメータの書き換え対策（SQLインジェクション対策等）を行う。

## 6. 先行タスク（Predecessor）機能 要件

### 6.1. 機能概要

あるスケジュール（タスク・期間予定）が「依存する先行スケジュール」を複数指定できる機能。  
ガントチャート上で依存関係を矢印で可視化し、スケジュール管理の精度を高める。

### 6.2. 機能要件

* **先行タスクの登録・編集・削除**:
  * 管理画面のスケジュール編集フォームに「先行タスク」選択UIを追加する。
  * 1つのスケジュールに対して0件以上の先行スケジュールを設定できる。
  * 循環依存（A→B→A のような循環）は許容しない（登録時バリデーションで防止）。
* **依存関係の保存**:
  * schedule_predecessors テーブルに (schedule_id, predecessor_id) ペアとして格納する。
  * スケジュール削除時は、関連する schedule_predecessors レコードも自動削除（CASCADE）。
* **ガントチャートへの可視化**:
  * index.php のガントチャート上で、先行タスク→後続タスクの方向に矢印を描画する。
  * 矢印は先行タスクバーの終端から後続タスクバーの始端へ引く。
  * 一般閲覧者にも表示する（is_public = 1 のタスクのみ対象）。

### 6.3. 非機能要件

* 先行タスクの件数が多い場合でも、ガントチャートの描画パフォーマンスを維持する。
* 既存の schedules テーブル・schedule_segments テーブルのスキーマ変更なし（後方互換維持）。
