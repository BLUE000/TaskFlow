# TaskFlow テスト仕様書 (Test Specification)

V字モデルに基づき、各設計フェーズに対応するテストケースを定義します。テスト実行時は、本仕様書に従って合否（Pass/Fail）を判定します。

---

## 1. 単体テスト仕様 (Unit Test)
**【対応設計: 詳細設計 (モジュール・クラス設計)】**
PHPおよびC++の暗号化/復号ラッパー `CryptoUtil` の独立した動作を検証します。

### 1.1. PHP 側 `CryptoUtil` 単体テスト
| テストID | テストケース名 | 入力データ/条件 | 期待される結果 (判定基準) |
| :--- | :--- | :--- | :--- |
| UT-PHP-01 | 空文字の暗号化 | `$plainText = ""` | 空文字 `""` が返却されること。 |
| UT-PHP-02 | 正常な暗号化・復号 | `$plainText = "Hello TaskFlow"` | 暗号化結果がBase64文字列であり、それを復号すると元の `"Hello TaskFlow"` に完全に一致すること。 |
| UT-PHP-03 | 空文字の復号 | `$cipherText = ""` | 空文字 `""` が返却されること。 |
| UT-PHP-04 | 不正なBase64の復号 | `$cipherText = "InvalidBase64#$@"` | `InvalidArgumentException` がスローされること。 |
| UT-PHP-05 | 異なる秘密鍵での復号 | 暗号化時キー: `key-A`<br>復号時キー: `key-B` | 復号処理時に `RuntimeException` がスローされること。 |
| UT-PHP-06 | 接続エラー時の挙動 | API URLに無効なホストを指定 | 接続エラーを検知し、`RuntimeException` がスローされること。 |

| IT-SYNC-01 | ローカル新規追加の同期 | 同期完了状態 ($T_{sync}$ 同期済) | 1. SQLiteに新規タスクA(UUID)を追加。<br>2. 同期を実行。 | MySQL上にタスクAが反映され、双方の `updated_at` が一致すること。 |
| IT-SYNC-02 | リモート新規追加の同期 | 同期完了状態 ($T_{sync}$ 同期済) | 1. MySQLに新規タスクB(UUID)を追加。<br>2. 同期を実行。 | SQLite上にタスクBが反映され、双方の `updated_at` が一致すること。 |
| IT-SYNC-03 | 論理削除の同期 | 同期完了状態 ($T_{sync}$ 同期済) | 1. SQLiteでタスクAを論理削除 (`is_deleted=1`)。<br>2. 同期を実行。 | MySQL上のタスクAも `is_deleted=1` に更新されること。 |
